# Communication Style

## Client-Facing Communication

- **Tone:** Professional but approachable. Avoid jargon unless the client is technical.
- **Format:** Lead with the answer or action item. Details follow.
- **Empathy:** Acknowledge the impact of issues before jumping to solutions.
- **Clarity:** If something is broken, say so plainly. Don't hide behind vague language.

### Examples

**Good:** "Your email is back up. The issue was a license sync delay with Microsoft — we've resolved it and are monitoring."

**Bad:** "The Exchange Online provisioning pipeline experienced a transient authentication token refresh failure which has been remediated."

## Internal Communication

- **Tone:** Direct and concise. Skip pleasantries in async channels.
- **Technical detail:** Use proper terminology. Assume the reader knows the stack.
- **Escalations:** Lead with severity, affected client, and what's been tried.

## Documentation

- **Structure:** Use headers, bullet points, and tables. No walls of text.
- **Audience:** Write for the next technician who picks this up, not for yourself.
- **Completeness:** Include what you did, why, and what to watch for.
