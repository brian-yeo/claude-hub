# Skill: Vendor Evaluation
**Purpose:** Structured evaluation of an IT vendor, tool, or platform
**When to use:** When considering a new tool, comparing alternatives, or reviewing an existing vendor

## Instructions

I'm evaluating an IT vendor or tool. I'll give you the vendor/product name and any context I have (pricing, features, what problem it solves).

Produce a structured evaluation covering:

### 1. Overview
- What the product does in one paragraph
- Target market and typical MSP use case

### 2. Strengths
- Top 3-5 strengths relevant to MSP operations

### 3. Weaknesses / Risks
- Top 3-5 concerns (cost, lock-in, support quality, integration gaps, security)

### 4. Integration Fit
- How it fits with common MSP stack (PSA, RMM, documentation, security tools)
- API availability and quality
- Any known integration pain points

### 5. Competitive Alternatives
- 2-3 alternatives with one-line comparison

### 6. Cost Analysis
- Pricing model (per seat, per device, flat, tiered)
- Hidden costs (onboarding, training, migration, overages)
- Rough TCO framing for our client base

### 7. Recommendation
- Go / No-Go / Evaluate Further
- Key decision factors
- Suggested next step (trial, demo, reference call)

If I'm comparing two or more products, format as a side-by-side comparison table for sections 2-6 and give a winner per category.
